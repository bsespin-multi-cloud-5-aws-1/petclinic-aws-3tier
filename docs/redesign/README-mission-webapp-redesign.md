# 미션 동물병원 리디자인

## 바로 확인하기
- `webapp/index.html`을 브라우저로 열면 서버 없이 홈 디자인과 배경 영상을 볼 수 있습니다.
- 미리보기의 보호자 등록·조회·수의사 링크는 기능 안내 페이지로 이동합니다. 데이터 입력 기능은 Spring 서버에서 실행되는 JSP에 연결되어 있습니다.

## 기존 프로젝트 적용
1. 기존 `src/main/webapp`을 백업합니다.
2. 이 ZIP의 `webapp` 내용을 기존 프로젝트의 `src/main/webapp`에 덮어씁니다.
3. 기존 프로젝트 방식으로 WAR를 다시 빌드하고 배포합니다. Java 소스·DB·pom.xml 변경은 없습니다.
4. 새 디자인은 `resources/css/mission.css`에서 수정합니다. 기존 LESS를 컴파일한 뒤에도 htmlHeader.tag에서 이 CSS를 마지막에 불러옵니다.
5. 기존 구조가 CloudFront `/images/*`를 S3로 라우팅한다면, `webapp/images/hero/hero.mp4`를 해당 버킷의 `images/hero/hero.mp4` 키로 업로드하고 기존 파일 캐시를 무효화합니다. Content-Type은 `video/mp4`입니다. 외부 저장소 업로드는 이 작업에서 수행하지 않았습니다.
6. WAR에서 직접 정적 파일을 제공하는 구성에서는 JSP의 context-aware Spring URL과 기존 default-servlet-handler를 통해 영상을 제공합니다.

## 포함 내용
- 수정된 홈 JSP, 공통 헤더·메뉴·푸터·레이아웃
- 별도 CSS/JS와 서버 없는 디자인 미리보기
- `images/hero/hero.mp4`: 4개 무료 스톡 영상 편집본, 약 34초, 1280×720, 24fps, H.264, 무음, faststart
- 0.8초 크로스페이드와 시작·끝 페이드, 재생/정지 버튼, 모바일 메뉴, 동작 줄이기 설정 지원
- 기존 보호자·반려동물·방문·수의사 JSP와 폼 태그 보존
- 기존 컴파일 CSS도 포함하여 미리보기에서 동일한 스타일 충돌을 확인

## 확인 범위
영상 전체 프레임 디코딩, 파일 경로, 기존 입력 JSP 보존, JS 구문, JSP 레이아웃 정적 검사를 수행했습니다. 브라우저에서 홈, 작은 화면의 가로 넘침, 영상 일시정지, 모바일 메뉴와 Escape 닫기를 확인했습니다.

이 환경에는 Java/Maven 실행 환경이 없어 Tomcat에서 JSP 컴파일 및 DB 연결까지 실행하지는 않았습니다. 기존 전화번호·주소·진료시간은 제공된 사이트의 값을 유지했으므로 실제 운영 정보와 맞는지 배포 전에 확인해 주세요. ‘진료 예약’으로 표시되던 보호자 생성 링크는 실제 동작에 맞춰 ‘보호자 등록’으로 정리했습니다.

원본 ZIP에 기존 hero.mp4는 포함되어 있지 않아 신규 스톡 영상 4개로 구성했습니다.
